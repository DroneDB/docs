# AGENTS.md

## Project Overview
DroneDB Docs — Docusaurus v3 documentation site deployed at docs.dronedb.app. The site is a
**Hub-first user guide**: most readers use DroneDB Hub in a browser, not a terminal.

## Build & Run
| Command | Description |
|---------|-------------|
| `npm start` | Dev server with hot reload (English) |
| `npm start -- --locale it` | Dev server for one locale |
| `npm run build` | Production build of every locale → `build/` |
| `npx docusaurus build --locale en` | Faster build of English only |
| `npm run serve` | Serve production build locally |

Node ≥18 required. `docusaurus build` runs `yarn --version`; without yarn installed, put a script
that prints a version on `PATH`.

## Structure
| Section (navbar) | Folder | Audience |
|------------------|--------|----------|
| Get started | `docs/get-started/` | New Hub users |
| Hub guide | `docs/hub-guide/<group>/` | Hub users: one task per page |
| Self-hosting | `docs/self-hosting/` | People who run their own Registry |
| Developers | `docs/developers/` | CLI, library, REST/STAC/OGC APIs |
| Reference | `docs/reference/` | Formats, glossary, FAQ |

- One sidebar per section in `sidebars.js`, written by hand: a new page must be added there.
- Moved pages keep their old URL through `redirects.js`.
- Formats and entry types exist only in `src/data/formats.json` (rendered by `<FormatTable>`).

## Hub guide pages
Front matter: `title`, `description`, `hub_feature` (coverage report), `datasets` (link check),
`requires` (rendered by `<Requires>`). Body: media first, then `<Requires />`, `<TryLive>`,
`## When to use it`, `## Steps`, `## Options`, `## Limits & requirements`, `## Related`, and an
optional `<ForDevelopers>` box. At most 600 words of prose and one `<LiveEmbed>` per page.
CLI commands, API calls and implementation detail go to `docs/developers/` or
`docs/self-hosting/`; on a Hub guide page they appear only inside `<ForDevelopers>`.

## MDX components (no import needed, `src/theme/MDXComponents.js`)
| Component | Use |
|-----------|-----|
| `<Screenshot id alt caption />` | Captured image `static/media/<id>.webp` |
| `<Clip id caption />` | YouTube clip behind its poster; the id maps to a `youtubeId` |
| `<TryLive org ds path view hint />` | Button that opens a public dataset on hub.dronedb.app (`compare="a.tif,b.tif"` opens the compare view) |
| `<LiveEmbed org ds path view poster />` | Live Hub viewer, loaded on click |
| `<Steps>` | Numbered steps around a Markdown ordered list |
| `<ForDevelopers cli api>` | Collapsed box with the CLI or API way |
| `<Requires />` | "Requires:" line from the `requires` front matter |
| `<FormatTable category />` | Formats table from `src/data/formats.json` |

Hub URLs are built only in `src/lib/hub.mjs`.

## Media
- Screenshots and clips are generated by the capture pipeline in `media-capture/`, never made
  by hand. Shot ids are `<section>/<feature>--<shot>`; the image is `static/media/<id>.webp`.
- `src/data/media.json` (generated) lists every captured shot with its size and YouTube id.
  A shot that is not captured yet renders as a placeholder and the build prints `[media]`.

## Pitfalls
- `build/` is in `.gitignore` — not tracked in git. Deployment uses a separate CI/CD pipeline.
- Broken links cause build errors (`onBrokenLinks: 'throw'`); broken anchors warn only.
- In MDX, Markdown inside a component (for example a list inside `<Steps>`) needs blank lines
  around it.
- An iframe of Hub must use `?embed=1`; Registry blocks framing otherwise.
