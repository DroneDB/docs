# Reference

`ddb` is a command line interface (CLI) to access DroneDB's functions. This makes it ideal for power users and for creating automated workflows.

See the [CLI Overview](/docs/cli) page for a quick command summary and links to tutorials.

## Quick Examples

Below are concise examples for commands not covered in the [Examples](/docs/cli/examples) page.

### Projecting images

Project images onto a georeferenced map:

```bash
ddb geoproj images/DJI_0018.JPG -o projected/
```

### Creating static tiles (XYZ/TMS)

Generate tiles for GeoTIFFs, drone images and [COPC](https://github.com/OpenDroneMap/cloud-optimized-point-cloud) point clouds. Similar to [gdal2tiles.py](https://gdal.org/programs/gdal2tiles.html) but faster and with more format support:

```bash
ddb tile DJI_0018.JPG output_tiles/
ddb tile orthophoto.tif output_tiles/
```

### Building COPC point clouds

Build COPC (Cloud Optimized Point Cloud) files for efficient streaming:

```bash
ddb copc output/ point_cloud.laz
```

Supported input formats: LAS, LAZ, E57, PTS, XYZ, PLY.

### Generating Cloud Optimized GeoTIFFs (COG)

Convert standard GeoTIFFs to COGs for efficient streaming with range requests:

```bash
ddb cog output.tif input.tif
```

### Extracting GPS locations/footprints to GeoJSON

```bash
# GPS points
ddb info *.JPG -f geojson -o gps.geojson

# Image footprints (polygons)
ddb info *.JPG -f geojson --geometry polygon -o footprint.geojson
```

### Generating STAC Catalogs

Generate STAC-compliant JSON for interoperability:

```bash
cd my-dataset/
ddb stac

# For a specific file
ddb stac -p orthophoto.tif
```

### Building 3D Model Tiles

Generate Nexus files for efficient web streaming of 3D meshes:

```bash
ddb nxs model.obj output.nxz
```

Supported input formats: OBJ, GLTF, GLB.

Generate OGC 3D Tiles (`tileset.json` + `b3dm`) for the unified 3D viewer (requires the optional Obj2Tiles binary):

```bash
ddb 3dtiles model.obj ./3dtiles

# Force a local (non-georeferenced) tileset
ddb 3dtiles model.obj ./3dtiles --local

# Explicit WGS84 origin
ddb 3dtiles model.obj ./3dtiles --lat 43.7 --lon 10.4 --alt 50
```

### Generating Thumbnails

```bash
ddb thumbs *.JPG -o thumbs/
ddb thumbs orthophoto.tif -o thumb.jpg -s 1024
```

### Re-processing indexed files after an upgrade

When you upgrade DroneDB to a version that extracts additional metadata or supports new file types, use `rescan` to update all metadata in place:

```bash
cd my-dataset/
ddb rescan

# Only specific types
ddb rescan --type image,pointcloud

# Continue even if some files fail
ddb rescan --continue-on-error
```

## Environment Variables

:::tip
For practical workflow examples (multispectral, terrain analytics, clone/push, metadata), see the [Examples](/docs/cli/examples) page.
:::

DroneDB reads the following environment variables at runtime. Variables marked **GDAL config** can also be set via `CPLSetConfigOption()` in the GDAL C API.

### General

| Variable | Description |
|----------|-------------|
| `DDB_LOG` | If set (any value), enables logging to file (`ddb-log.csv`) in the current directory. |
| `DDB_DEBUG` | If set (any value), enables verbose debug output on the console. Equivalent to passing `--debug`. |
| `DDB_HOME` | Override the DDB home directory (default: `~/.ddb`). Stores credentials and user profile. |
| `DDB_DATA` | Override the DDB data directory used for bundled data files (timezone database, etc.). |

### Point Cloud (COPC)

| Variable | Description |
|----------|-------------|
| `DDB_UNTWINE_PATH` | Absolute path to the `untwine` binary. When set, this path is authoritative: if it does not point to a valid executable, Untwine is considered unavailable. Useful for pinning the backend or running tests. |
| `DDB_USE_PDAL_COPC` | Set to `1` to force the PDAL COPC backend, bypassing Untwine. |
| `DDB_COPC_BACKEND` | Explicit backend selection: `"untwine"`, `"pdal"`, or `"auto"` (default). Unknown values are silently ignored. `DDB_USE_PDAL_COPC=1` takes precedence. |

### COG Build (GDAL config)

These variables control `ddb build` and `ddb cog` for GeoRaster entries. They are read via `CPLGetConfigOption` and can also be passed as standard environment variables.

| Variable | Default | Description |
|----------|---------|-------------|
| `DDB_COG_JPEG_QUALITY` | `75` | JPEG quality (1–100) for COG compression. Applied only to 8-bit RGB or RGBA rasters. LZW is used for all other cases. |
| `DDB_WARP_MEMORY_MB` | `512` | GDALWarp memory buffer size in MB (`-wm` flag). Larger values reduce chunking overhead when multi-threading is active. |
| `DDB_COG_CACHE_MB` | `1024` | GDAL block cache size in MB during a COG build. The cache is set to this value for the build (raised or lowered) and the previous value is restored when the last concurrent build ends. |
| `DDB_BUILD_THREADS` | `min(8, cores)` | Threads one COG build uses for warping and compression (GDAL `NUM_THREADS`). `0` uses all cores. Lower it when several builds run at the same time. |
| `DDB_GDAL_CACHE_MB` | `1024` | Upper bound for GDAL's process-wide block cache, applied at start-up (GDAL's own default is 5 % of RAM). Never raises the cache. Ignored when `GDAL_CACHEMAX` is set. |

A COG build needs about `DDB_COG_CACHE_MB` + `DDB_WARP_MEMORY_MB` + 1 GB of driver temporaries: 2.4 GB was measured for a 72 MB, 40 001 × 90 001 px thermal mosaic with the defaults.

### Index connections (library hosts)

Programs that use the DroneDB library (Registry, the language bindings) keep idle index connections and reuse them for the next call on the same dataset: a reused connection skips the SQLite open, the SpatiaLite set-up and the schema parse (about 0.8 ms per call). The `ddb` command runs one command per process and does not keep connections.

| Variable | Default | Description |
|----------|---------|-------------|
| `DDB_DB_POOL_SIZE` | `4` | Idle connections kept per dataset. `0` disables the reuse. |
| `DDB_DB_POOL_MAX` | `64` | Idle connections kept in total. Each holds about 1 MB, plus up to 2 MB of SQLite page cache. |
| `DDB_DB_POOL_IDLE_SECONDS` | `60` | Idle connections are closed after this many seconds. |

A connection is reused only if the dataset's `.ddb/dbase.sqlite` is still the same file. A host that deletes, moves or replaces a dataset folder calls `DDBReleaseConnections` first; Registry does this.

### Map tiles and renders (library hosts)

Programs that use the DroneDB library also keep the rasters and point clouds they tile or render open between calls. A tile of a raster seen recently skips the open, the coordinate system set-up and the reprojection set-up (about 2–3 ms per tile) and reuses GDAL's block cache; a point-cloud tile skips the COPC header read. Band statistics used to stretch non-8-bit rasters (DSM, thermal, multispectral) come from the raster, from the `.stats.json` file written next to a built COG, or are computed once per version of the file.

| Variable | Default | Description |
|----------|---------|-------------|
| `DDB_RASTER_CACHE_SIZE` | `8` | Idle tilers (or open rasters) kept per file. `0` disables the reuse. |
| `DDB_RASTER_CACHE_MAX` | `64` | Idle tilers and open rasters kept in total. |
| `DDB_RASTER_CACHE_IDLE_SECONDS` | `60` | Idle ones are closed after this many seconds. |
| `DDB_PCTILE_RESOLUTION_OFFSET` | `2` | A point-cloud tile reads the COPC levels down to the resolution of this many zoom levels above the tile (`2`: 4× the tile's pixel size). |

A kept raster is used again only while the file has the same modification time, size and (on Linux and macOS) inode, so a rebuilt COG is opened again. `DDBReleaseConnections` also closes the rasters kept under the folder; builds close those of the output they replace.

Tiles are PNG (zlib level 1), JPEG or WebP (`DDBMemoryTileFmt` with `"webp"`, lossy, quality 80). A tile without transparent pixels has no alpha band. Thumbnails are WebP at quality 80; only non-8-bit images are stretched to the 0–255 range.

### Gaussian Splats

| Variable | Default | Description |
|----------|---------|-------------|
| `DDB_GSPLAT_SH_BITS` | SPZ defaults | Override spherical-harmonics bit depth for SPZ packing. One value (`5`) sets `sh1Bits`; two comma-separated values (`5,4`) set `sh1Bits` and `shRestBits`. Each value must be between `1` and `8`. |
