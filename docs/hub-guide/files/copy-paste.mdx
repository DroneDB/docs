## When to use it

Copy files to make a second version of them. Move files to put them in another folder or in
another dataset. You can copy from any dataset that you can read, also a public one, into a
dataset where you can write.

## Steps

<Steps>

1. Select one or more files or folders.
2. Press Ctrl+C (Cmd+C on a Mac), or right-click and click **Copy**. To move the files, press
   Ctrl+X or click **Cut**.

   <Screenshot id="files/copy-paste--context-menu" />

3. Items that you cut are dimmed in the file list until you paste them or clear the clipboard. A clipboard panel at the bottom right shows **Copy** or **Cut**, the source and the items. Click
   **Clear clipboard** in it to empty the clipboard.

   <Screenshot id="files/copy-paste--clipboard-panel" />

4. Open the destination folder. It can be in another dataset: open that dataset in the same browser
   tab.
5. Press Ctrl+V, or right-click and click **Paste**.
6. If files with the same names are in the destination, the **Paste Conflict** window opens. Click
   **Skip All**, **Overwrite All** or **Cancel**. When you paste a cut into the dataset that it comes
   from, nothing can be replaced (a move never replaces a file): the window asks, file by file, to **Keep
   both** (the moved file gets a new name) or **Skip**. The items that were not moved stay on the clipboard.

   <Screenshot id="files/copy-paste--conflict" />

</Steps>

A copy stays on the clipboard, so you can paste it again. A cut is used once.

## Transfer to another dataset

**Transfer** moves files to another dataset without the clipboard. If you can only read the
source dataset, the menu shows **Copy to another dataset...** instead: it copies the files, and they
stay in the source.

1. Select the files, right-click and click **Tools** › **Transfer** (or **Tools** › **Copy to another
   dataset...**).
2. Select the **Destination Organization** and the **Destination Dataset**.
3. Type a **Destination Path (optional)**, for example `folder/subfolder`, or leave it empty for the
   root folder. Select **Overwrite existing files** if necessary.
4. Click **Transfer** (or **Copy**). A note above the destination says if the files move or are copied.

## What happens

| Action | Same dataset | Another dataset |
|---|---|---|
| Copy, then paste | A copy in the new folder | A copy; the source stays |
| Cut, then paste | A move | A move; the files leave the source |
| Transfer | — | A move; the files leave the source |
| Copy to another dataset | — | A copy; the source stays |

A copied or moved file keeps its builds, so Hub does not build it again. Files that a
build waits for (for example the `.mtl` of a model) start that build when they arrive.

## Limits & requirements

- Paste, **Transfer** and **Copy to another dataset...** need write access to the destination
  dataset.
- A move (Cut or **Transfer**) needs write access to the source dataset. With read access only,
  **Cut** does not show and the server refuses a move.
- You cannot paste into the folder that the items come from.
- The clipboard is kept in the browser tab. It stays after a reload, and it is empty in a new tab.
- **Transfer** and **Copy to another dataset...** are not available while a file of the selection is
  building.
- A paste where some items fail shows a summary window with the moved, skipped and failed items.
