## When to use it

You have the photos of a drone flight and you want an orthophoto, a DSM or DTM, a point cloud or a textured
3D model. Hub sends the images to a processing node (NodeODX, the engine of OpenDroneMap) and puts the results
back into a dataset.

## Steps

<Steps>

1. [Upload the images](/docs/get-started/upload) into a folder of a dataset, for example `images`.

2. Open the **Tasks** tab of the dataset. Click **Run Photogrammetry**.

   <Screenshot id="processing/photogrammetry--tasks-button" />

3. In **Image folder**, type the folder or click the folder button to find it. Leave it empty to use
   every image of the dataset. All images under the folder are processed.

4. If the server has more than one node, select the **Processing node**. Click **Check Node** to see if
   the node answers, how many tasks it has and how many it runs at once, for example **Node reachable - 1
   running, 0 waiting, max 1 parallel**, with its engine and version.

5. Select a **Processing profile** (see the table below). The line under the list says what the profile
   makes.

   <Screenshot id="processing/photogrammetry--dialog" />

6. Optional: type a **Task name**. It shows in the **Tool** column of the task list, so that two runs can be told apart.
   Change single options in the options editor under the profile (see **Options**). The window is 90 % of the screen high and the options list fills it. On a screen 1600 px wide or more, the list stands beside the fields; a phone keeps one column.

7. Select where the results go:
   - **Output folder**: a folder of this dataset (default `photogrammetry_output`).
   - **Create new dataset for results**: type a **New dataset name** and select its **Visibility**
     (default **Private**). The name is a slug: 2 to 128 lowercase letters, digits, `_` and `-`, starting
     with a letter or a digit, with no `--`. The line under the field shows the rule of your server. The
     dataset is made in the same organization, when the results are imported at the end of the run.

8. Click **Start**. Hub checks the node first and shows one toast. If the node does not answer, Hub asks
   before it starts the task.

9. Follow the task in the **Tasks** tab. The row shows the current stage of the run next to the bar, for example
   **opensfm**, **openmvs**, **meshing**, **texturing**, **DEM** or **orthophoto**, and the stage never goes back.
   A task that waits for the node says so. Click **View log** (the terminal button) to read what the node does.

   <Screenshot id="processing/photogrammetry--progress" />

10. When the task ends, the results are in the output folder. Hub then [builds](/hub-guide/processing/builds.mdx) them, so
    they open on the map and in the viewers. The builds of a run give one toast when the last of them ends, for
    example **Photogrammetry finished - 9 files built** (with the names in the detail), and the **Tasks** tab folds
    the builds that succeeded under the run, with their count. A build that failed stays in the list.

    <Screenshot id="processing/photogrammetry--results" />

</Steps>

## Processing profiles

| Profile | What it makes |
|---|---|
| **3D Model (mesh)** | A high-quality 3D mesh and a dense point cloud. Best for structures and buildings |
| **Custom (JSON array)** | What you type: the options as a JSON array |
| **Default - Orthophoto + DSM** | An orthophoto and a Digital Surface Model (the default) |
| **DSM + DTM (terrain)** | A DSM and a Digital Terrain Model, for topography and volumes |
| **Fast Orthophoto** | An orthophoto only. Faster, lower quality, no 3D products |
| **High Resolution (1 cm/px)** | An orthophoto and a DSM at 1 cm per pixel. Much slower |
| **Multispectral** | Radiometric calibration of a multispectral camera, and a DSM |
| **Volume Analysis** | A DSM with a dense point cloud, for [stockpile volumes](/hub-guide/analyse/stockpile.mdx) |

## Options

The options editor lists every option of the node, in groups.

| Control | What it does |
|---|---|
| **Search** | Finds an option by its name. It opens the groups that have a match, and says **No options match "your text"** with a **Clear search** button when none does. `Esc` empties the search and keeps the window open |
| **Flat View** / **Grouped View** | Shows the options in one list or in groups |
| **Expand All** / **Collapse All** | Opens or closes every group |
| **… changed** | The number of options you changed |
| **Customized options** | One button per changed option. Click it to go to that option |
| **Reset … to default** (the arrow on a changed option) | Puts the option back to the value of the profile and removes it from **Customized options** |

Each option shows its help, with the allowed values and the default filled in.

An option you change replaces the value of the profile. The other options of the profile stay. When you
switch the profile, an option you changed that equals the value of the new profile goes back to the profile:
**Default - Orthophoto + DSM**, then **Fast Orthophoto**, then **Default - Orthophoto + DSM** again sends no
options of its own.

## Limits & requirements

- You need write access to the dataset.
- The server needs a processing node. Without one, the **Run Photogrammetry** button is not shown. When
  your account or organization cannot use processing, the button is grey and its tooltip says why.
- On DroneDB Hub, every [plan](/hub-guide/account/plans.mdx) includes processing. The plan sets the priority.
- The results count toward the storage of the owner of the organization, also when you are a member. **Start** is
  refused when the owner has no space left or the estimate does not fit, and a run that runs out of space fails and
  Hub removes what it added.
- Hub imports the results without the internal folders of the run (`entwine_pointcloud/`, `opensfm/` and
  `odm_meshing/`): they hold hundreds of chunk files that would show as separate point clouds. The point cloud
  that Hub builds comes from the georeferenced model. The task log counts the files that it left out. An
  administrator can change the folders ([Configuration](/self-hosting/configuration.mdx#processingplatform)).
- When you click **Start**, the name and your write access in the organization are checked: a name that is
  already taken there is refused with a message that names it, and nothing is created. The server checks
  again when the results are imported. If someone took the name during the run, or you lost write access,
  the task fails with a message that says so, and the results are not imported. **Retry** on a failed task
  does not fail on a dataset that the first run made.
- If you cancel the task, or it fails, Hub deletes the result files that it added to the dataset. The
  images and the other files stay. A dataset that the task created is deleted a few minutes later if it is
  still empty. See [Tasks panel & logs](/hub-guide/processing/tasks.mdx).
- Processing time depends on the number of images, the profile and the node. A small flight takes minutes; a
  large one can take hours.
