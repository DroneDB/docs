## When to use it

Long jobs run in the background as **tasks**: builds, photogrammetry, band merges, alignments, border masking, raster exports,
archive extraction, URL imports, ZIP downloads and more. The **Tasks** tab of a dataset lists them. Use it to
see what runs, why a file is not ready, or to get the result of a task.

## Steps

<Steps>

1. Open the dataset and click the **Tasks** tab. A link to the dataset that ends with `?tab=tasks`, such as the one in a [task e-mail](/hub-guide/account/build-notifications.mdx), opens this tab.

2. Find the task. The newest task is at the top. To filter the list, select a state in **All States** (**Cancelled or deleted** also lists the tasks that a user cancelled; **Enqueued** includes the tasks that wait on a node) or a
   tool in **All Tools**; the x in the list clears one filter, and **Clear filters** clears them all (it is also in
   the empty list that the filters leave). Click the header **State**, **Tool** or **Created** to sort. Click
   **Refresh** to read the list again. On a phone, each task is a card.

3. Read the row:
   - **State**: an icon. Point at it to read the state, for example **Enqueued**, **Processing**,
     **Succeeded**, **Failed**, or **Cancelled** for a task that a user stopped: point at it to see who.
     A task that waits in the queue of a processing node says **Queued on node**.
   - **Tool**: the task type, its version and the files it works on. A tool names its files, for example
     the folder of a photogrammetry run, so two runs can be told apart.
   - **Progress**: a bar and the current step. A build of a georaster shows its percent and its phase under
     the bar: **warping** (the raster is reprojected to the web map grid), **overviews**, **compressing** and **publishing**,
     so a build of a large orthophoto, which can take minutes, shows that it moves. A raster that is on the grid already has no
     **warping**. A build of another kind of file (a point cloud, a model, a splat) keeps a bar without a percent until it ends.
     A build that waits for another build of the dataset to end is **Enqueued** and says **Waiting behind** and the
     path of the build that runs. A failed task shows no bar: it shows a red **Failed**
     tag and why the task failed, for example "The file is damaged or not a valid GeoTIFF". Point at
     the reason to see the error type. The last line of the log gives the same reason.
     A build that waits for a missing companion file (for example the `.mtl` of an `.obj`) shows a
     yellow **Waiting for files** tag with the missing names. Its task ended, but the build starts again
     when you upload those files. See [Builds](/hub-guide/processing/builds.mdx). A cancelled task shows
     **Cancelled at 42 %**, the progress it had reached.
   - **Created** and **Duration**: when the task started and how long it ran. A running task shows a
     stopwatch. A task that waited in the queue before it started, for a second or more, also says
     **waited 50s**, so a long run is not mistaken for a slow one.

4. Click **View log** (the terminal button) to open the log. The title of the window names the tool, the
   files, the dataset and the time of the task.

   <Screenshot id="processing/tasks--log" />

5. In the log window, **Auto-refresh** reads the log again every 2 seconds while the task runs.
   **Auto-scroll** keeps the last line in view. **Wrap lines** (on by default) wraps a long line; switch it
   off to keep each line whole and scroll the log sideways. The window is wide, so a log line fits, and you
   can maximize it. Click **Close** when you are done.

</Steps>

## Actions

| Button | What it does | Shown for |
|---|---|---|
| **View log** | Opens the last lines of the log | Every task |
| **Result** | Downloads the result file. Point at it to see until when it is available | A finished task that makes a file, for example a raster export or a ZIP download |
| **Cancel** | Stops the task, after you confirm. For a task that adds files, the confirmation says what is deleted. A toast says **Task cancelled** | A running or waiting task, except one that can no longer be cancelled (see below) |
| **Retry** (tooltip **Run again from the beginning**) | Runs the task again from the beginning. The row turns **Enqueued** at once and a toast says **Task queued again**. Hub checks it like a new task, so it can be refused with a message | A failed task. Not a succeeded or a cancelled task, and not a task that already saved its result |
| **Delete from history** | Removes the task and its result file, after you confirm | A finished task |
| **Clear Concluded** | Removes every finished task of the list, and their result files | The toolbar |
| **Run Photogrammetry** | Starts [photogrammetry](/hub-guide/processing/photogrammetry.mdx) | The toolbar, when the server has a processing node |

## Cancel and failure of a task that adds files

- Some tasks add files to a dataset: an import of a dataset or a file from a URL, an archive extraction,
  a merge of multispectral bands, an alignment of a raster and photogrammetry. If such a task is
  cancelled or fails, Hub deletes the files that the task added. The files that were in the dataset before,
  and the files that other users add meanwhile, stay. The same happens if the server restarts during the
  task.
- A dataset that the task created is deleted a few minutes later if it is still empty.
- **Cancel** is not offered for a task that can no longer be cancelled: a merge with **Delete source
  files after merge**, or an extraction that deletes its archive, once it has started to delete its
  sources. If such a task is lost because the server restarts, it ends **Failed** and names the sources
  that remain. **Retry** then answers that the task cannot run again.
- A failed import shows its reason as the error of the task.

## Limits & requirements

- Anyone who can read the dataset sees its tasks.
- The log and the result of a task are for the user who started it, the owner of the organization and the
  administrators. Tasks that the server starts by itself are open to every reader.
- **Cancel**, **Retry**, **Delete from history** and **Clear Concluded** need write access. A row shows only
  the buttons that you can use: a member who can only read sees no **Cancel**, and **View log** shows only for
  the tasks whose log you may read.
- A result file is kept for a limited time. After that, **Result** is not shown.
- The server limits how many tasks run at the same time, for you and for your organization. When you are at
  the limit, a new task is refused with a message. Wait for a task to end and try again.
