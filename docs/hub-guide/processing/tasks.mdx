## When to use it

Long jobs run in the background as **tasks**: builds, photogrammetry, band merges, alignments, raster exports,
archive extraction, URL imports, ZIP downloads and more. The **Tasks** tab of a dataset lists them. Use it to
see what runs, why a file is not ready, or to get the result of a task.

## Steps

<Steps>

1. Open the dataset and click the **Tasks** tab.

2. Find the task. The newest task is at the top. To filter the list, select a state in **All States** or a
   tool in **All Tools**. Click **Refresh** to read the list again.

3. Read the row:
   - **State**: an icon. Point at it to read the state, for example **Enqueued**, **Processing**,
     **Succeeded**, **Failed**, or **Deleted** for a task that you cancelled.
   - **Tool**: the task type, its version and the file or folder it works on.
   - **Progress**: a bar and the current step. A failed task shows no bar: it shows a red **Failed**
     tag and why the task failed, for example "The file is damaged or not a valid GeoTIFF". Point at
     the reason to see the error type. The last line of the log gives the same reason.
     A build that waits for a missing companion file (for example the `.mtl` of an `.obj`) shows a
     yellow **Waiting for files** tag with the missing names. Its task ended, but the build starts again
     when you upload those files. See [Builds](/hub-guide/processing/builds.mdx).
   - **Created** and **Duration**: when the task started and how long it ran. A running task shows a
     stopwatch.

4. Click **View log** (the terminal button) to open the log.

   <Screenshot id="processing/tasks--log" />

5. In the log window, **Auto-refresh** reads the log again every 2 seconds while the task runs.
   **Auto-scroll** keeps the last line in view. Click **Close** when you are done.

</Steps>

## Actions

| Button | What it does | Shown for |
|---|---|---|
| **View log** | Opens the last lines of the log | Every task |
| **Result** | Downloads the result file. Point at it to see until when it is available | A finished task that makes a file, for example a raster export or a ZIP download |
| **Cancel** | Stops the task, after you confirm | A running or waiting task |
| **Retry** | Runs the task again | A failed task |
| **Delete from history** | Removes the task and its result file, after you confirm | A finished task |
| **Clear Concluded** | Removes every finished task of the list, and their result files | The toolbar |
| **Run Photogrammetry** | Starts [photogrammetry](/hub-guide/processing/photogrammetry.mdx) | The toolbar, when the server has a processing node |

## Limits & requirements

- Anyone who can read the dataset sees its tasks.
- The log and the result of a task are for the user who started it, the owner of the organization and the
  administrators. Tasks that the server starts by itself are open to every reader.
- **Cancel**, **Retry**, **Delete from history** and **Clear Concluded** need write access.
- A result file is kept for a limited time. After that, **Result** is not shown.
- The server limits how many tasks run at the same time, for you and for your organization. When you are at
  the limit, a new task is refused with a message. Wait for a task to end and try again.
