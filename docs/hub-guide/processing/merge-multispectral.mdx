## When to use it

Many multispectral cameras save one file per band. Plant Health needs all the bands in one raster to compute
an index such as NDVI. Merge the band files into one GeoTIFF first. When you open a single-band raster in
Plant Health, the panel tells you to do this.

## Steps

<Steps>

1. Select the band files in the file browser. Hold **Ctrl** (**Cmd** on a Mac) and click each file. Select
   two files or more, all GeoTIFFs (`.tif` or `.tiff`).

2. Right-click the selection and click **Tools** → **Merge Multispectral Bands**.

   <Screenshot id="processing/merge-multispectral--menu" />

3. Put the bands in order under **Band Order**. Drag a band, or use its up and down arrows. The first band
   of the list is band 1 of the new file. A long file name is cut in the middle, so that the end that tells
   the bands apart (`_1`, `_NIR`) stays. Point at it to read the whole path.

4. Wait for the check. Hub shows the size, the number of bands and their data type, and an estimate of
   the file size, and the coordinate system when the bands have one. Errors and warnings show in the same
   place. A warning that the check gives for several files is said once, with its count, for example
   **(×5)**. If you change the order while the check runs, Hub ignores the old answer and checks again.

5. Look at the preview. It shows bands 1, 2 and 3 as red, green and blue. Click it to see it at full size.

6. Check the **Output path**. Hub proposes a name from the common start of the file names, with
   `_merged.tif` at the end, in the folder of the bands.

7. Optional: select **Delete source files after merge** to remove the band files when the merge ends.

8. Click **Merge**. The button is active only when the check found no error. The window shows the state of the task, as the Align window does: **Queued…**, the phase and the percent, **Done**, **Failed** with the reason, or **Cancelled**. It stays locked until the task ends. Click **Cancel** to stop it.

</Steps>

The merge runs as a task. Follow it in the [Tasks tab](/hub-guide/processing/tasks.mdx). The new file appears in the file
browser and is [built](/hub-guide/processing/builds.mdx) like any other raster. Open it in
[Plant Health](/hub-guide/analyse/plant-health.mdx).

## Options

| Option | What it does | Default |
|---|---|---|
| **Band Order** | The order of the bands in the new file | The order of the files in the file browser |
| **Output path** | The path of the new file in the dataset. Must be relative and not contain `..` | `<common name>_merged.tif` |
| **Delete source files after merge** | Deletes the band files after the merge | Off |

## Limits & requirements

- You need write access to the dataset.
- Hub checks that the files fit together: coordinate system, data type and alignment. It reprojects and
  resamples them to one grid.
- When a camera has several lenses, the bands can be shifted. If the shift is more than 2 pixels, Hub shows
  **Band misalignment detected** and, when it can, applies an approximate correction (it says so when none
  applies to the images). The window says to use **Run Photogrammetry** in the Tasks tab for an accurate
  result: select the **Multispectral** profile of
  [Photogrammetry](/hub-guide/processing/photogrammetry.mdx).
- **Delete source files after merge** cannot be undone. Once Hub has started to delete the band files,
  **Cancel** is not offered for the task. If the server restarts at that point, the task ends **Failed**
  and names the band files that remain, and **Retry** answers that the task cannot run again.
- If a file with the output path exists, the window says **This file exists and will be replaced**, and **Merge** asks **Replace “merged.tif”?** first (with the name of that file). Click **Replace** to go on, or **Cancel**. If the merge fails or you cancel it, that file stays as it was.
- If you cancel the merge, or it fails, Hub deletes the new file. The band files stay. See
  [Tasks panel & logs](/hub-guide/processing/tasks.mdx).
