Registry reads its settings from `appsettings.json` in the storage folder (`/data/appsettings.json`
in the container). The first start creates the file from the built-in defaults
(`appsettings-default.json`). After that, Registry does not rewrite the file: it only adds a
`Secret` or a `ThumbnailGeneratorToken` that is empty.

## How settings work

- **Where.** Almost every key is in the `AppSettings` section. Exceptions: `ConnectionStrings`,
  `Serilog` and `Ddb` are top-level sections.
- **Environment variables** win over the file. Write the path of the key with `__` between the
  parts: `AppSettings__ExternalUrlOverride=https://registry.example.com`,
  `AppSettings__Smtp__Password=…`, `ConnectionStrings__RegistryConnection=…`. An array item has its
  index: `AppSettings__KnownNetworks__0=172.16.0.0/12`.
- **Validation.** Registry checks the settings when it starts. An invalid value stops it (exit code
  `1`) and the message lists every failure with the name of its key. To check without starting,
  run `Registry.Web <storage folder> --check`: it reads the file and the environment like a start,
  writes nothing and exits `0` when the settings are valid. With Docker, run the new image with
  `--check` and the file mounted at `/data/appsettings.json`. `--check` does not check the
  [`IndexQueue`](#indexqueue) fields: Registry checks them when the index queue starts.
- **Restart.** A change takes effect when the Registry services restart.
- **Defaults.** "Default" below is the value a new `appsettings.json` has. Where the built-in value
  for an empty or missing key is different, the table says so. These keys have no built-in value: a
  file without them does not start (`TokenExpirationInDays`, `AuthCookieName`, `BatchTokenLength`,
  `RandomDatasetNameLength`, `UploadBatchTimeout`, `DatasetsPath`, `CachePath` and `DefaultAdmin`).
- **Time spans** are written `d.hh:mm:ss` or `hh:mm:ss`: `00:30:00` is 30 minutes, `1.00:00:00` is
  one day.

In the Hub, administrators can read the effective configuration in **Admin → Configuration**: see
[Admin pages](/self-hosting/admin-pages.mdx#configuration).

## Authentication

### AuthCookieName

The name of the cookie that carries the sign-in token. It must not be empty.

Default: `jwtToken`.

### AuthProvider

The database of users and roles (identity database):

- `Sqlite`: SQLite.
- `Mysql`: MySQL or MariaDB
  ([supported versions](https://github.com/PomeloFoundation/Pomelo.EntityFrameworkCore.MySql#supported-database-servers-and-versions)).

Change `ConnectionStrings:IdentityConnection` with it. Default: `Sqlite`.

### Secret

The key that signs the sign-in tokens (JWT). Registry generates a random value at any start where it is
empty (so the first start of a new storage folder, and a later one after you cleared it). Do not use the same secret for more than one deployment. A new value signs out
every user.

### TokenExpirationInDays

The number of days after which a sign-in token expires. At least `1`. Default: `7`.

### RevokedTokens

A list of tokens that Registry no longer accepts. Default: `[]`.

### ExternalAuthUrl

The URL of an external authentication service. When it is set, Registry sends the credentials of a
sign-in to it, and users, roles and metadata come from its answer: local user management is off.
It cannot be used with `LdapSettings`. Default: `null`.

### LdapSettings

LDAP or Active Directory sign-in. It cannot be used with `ExternalAuthUrl`. When `Enabled` is
`true`, `Server`, `BaseDn` and a `SearchFilter` with `{0}` are required. See
[LDAP / Active Directory](/self-hosting/ldap.mdx) for the setup and examples.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `Enabled` | `bool` | `false` | Turns on LDAP sign-in |
| `Server` | `string` | — | Host name or IP address of the LDAP server |
| `Port` | `int` | `636` | `389` plain LDAP, `636` LDAPS |
| `UseSsl` | `bool` | `true` | Use SSL/TLS (LDAPS) |
| `ValidateSslCertificate` | `bool` | `true` | Validate the certificate chain of the server |
| `BaseDn` | `string` | — | Base DN of the searches |
| `BindDn` | `string` | `null` | DN of the service account for the search. `null`: anonymous bind |
| `BindPassword` | `string` | — | Password of the service account |
| `SearchFilter` | `string` | `(sAMAccountName={0})` | Filter that finds the user; `{0}` is the escaped user name |
| `UserDnFormat` | `string` | `null` | Format of the user DN for a direct bind (no search) |
| `AdminGroupDns` | `string[]` | `[]` | DNs of the groups whose members get the `admin` role |
| `EmailAttribute` | `string` | `mail` | Attribute with the e-mail address |
| `DisplayNameAttribute` | `string` | `displayName` | Attribute with the display name |
| `GroupMembershipAttribute` | `string` | `memberOf` | Attribute with the group memberships |
| `Timeout` | `int` | `30` | Timeout of LDAP operations, in seconds |

### MonitorToken

A static token for the health checks `/quickhealth` and `/health`. A monitor sends it as
`Authorization: Bearer <token>` or as `?token=<token>`. Administrators can call the health checks
without it. `null` turns token access off. Default: `null`.

## Database

SQLite and the in-memory job queue need no setup. For production, and for every deployment with
processing nodes, use MySQL or MariaDB for all three stores. A processing node refuses to start with
`HangfireProvider` `InMemory`.

### Use MySQL / MariaDB instead of SQLite

1. Create the three databases and a user with rights on them (this is what the Compose setup runs):

   ```sql
   CREATE USER 'registry'@'%' IDENTIFIED BY 'password';
   CREATE DATABASE `RegistryData`;
   CREATE DATABASE `RegistryAuth`;
   CREATE DATABASE `RegistryHangfire`;
   GRANT EXECUTE, SELECT, SHOW VIEW, ALTER, ALTER ROUTINE, CREATE, CREATE ROUTINE,
         CREATE TEMPORARY TABLES, CREATE VIEW, DELETE, DROP, EVENT, INDEX, INSERT,
         REFERENCES, TRIGGER, UPDATE, LOCK TABLES
     ON `RegistryAuth`.* TO 'registry'@'%';
   -- repeat the GRANT for `RegistryData` and `RegistryHangfire`
   FLUSH PRIVILEGES;
   ```

2. Stop Registry and edit `appsettings.json`:

   ```json
   "AppSettings": {
     "AuthProvider": "Mysql",
     "RegistryProvider": "Mysql",
     "HangfireProvider": "Mysql"
   },
   "ConnectionStrings": {
     "IdentityConnection": "Server=db;Database=RegistryAuth;Uid=registry;Pwd=password",
     "RegistryConnection": "Server=db;Database=RegistryData;Uid=registry;Pwd=password",
     "HangfireConnection": "Server=db;Database=RegistryHangfire;Uid=registry;Pwd=password;Allow User Variables=true"
   }
   ```

3. Start Registry. The web server creates the tables. Processing nodes never migrate the
   databases.

Changing the provider does not copy data from SQLite.

### RegistryProvider

The database of organizations, datasets and jobs: `Sqlite` or `Mysql`. Change
`ConnectionStrings:RegistryConnection` with it. Default: `Sqlite`.

### HangfireProvider

The store of the background job queue:

- `InMemory`: in the memory of the process. Jobs that wait are lost at a restart.
- `Mysql`: MySQL or MariaDB.

Change `ConnectionStrings:HangfireConnection` with it. Default: `InMemory`.

### MySqlServerVersion

Optional. The MySQL or MariaDB version that Entity Framework writes SQL for, for example
`8.0.36-mysql` or `10.11.6-mariadb`. When it is empty, Registry asks the server once per process.
A wrong value makes Entity Framework write SQL for another server. Default: `null` (detected).

### ConnectionStrings

A top-level section with `IdentityConnection`, `RegistryConnection` and, for MySQL,
`HangfireConnection`. A new file has SQLite databases in the storage folder:

```json
"ConnectionStrings": {
  "IdentityConnection": "Data Source=./identity.db;Mode=ReadWriteCreate",
  "RegistryConnection": "Data Source=./registry.db;Mode=ReadWriteCreate"
}
```

The Hangfire connection to MySQL needs `Allow User Variables=true`.

## Storage

Relative paths are relative to the storage folder.

### StoragePath

The folder of the files that Registry keeps for itself: the [branding](#huboptions) files
(`branding/`, served at `/branding/`), the instance ID (`.instance-id`) and the saved e-mail
templates (`.email-templates.json`). Default: `./data`.

### DatasetsPath

The folder of the datasets. Required. Default: `./datasets`.

### TempPath

The folder of the temporary files. When it is empty, `./temp`. The DroneDB library keeps its cache
in `ddb-cache` under it. Default: `./temp`.

### CachePath

A folder that Registry requires and watches: it must not be empty, and its free disk space is part of
the health check (**Ddb cache path space health check**). Registry does not write its tiles and thumbnails
there: they go to the [`CacheProvider`](#cacheprovider) and to the `ddb-cache` folder of the DroneDB library
(`<TempPath>/ddb-cache`, see [`Ddb`](#ddb)). Default: `./cache`.

### DataProtectionKeysPath

The folder where the ASP.NET Core Data Protection keys are kept. Registry uses them, for example,
to encrypt the password of a source Registry during an import. When a web server and processing
nodes run as separate processes without Redis, set it to a folder that all of them share, or a
node cannot read what the web server encrypted. With Redis as `CacheProvider`, the keys are kept
in Redis and this key is not needed. Without either, each process keeps its own keys. Default:
`null`.

```json
"AppSettings": {
  "DataProtectionKeysPath": "./data/protection-keys"
}
```

## Cache

### CacheProvider

An additional cache:

- `null`: the memory of the process.
- `InMemory`:

  ```json
  { "type": "InMemory" }
  ```

- `Redis`: a Redis server, shared by all Registry processes. Redis also keeps the
  [data protection keys](#dataprotectionkeyspath).

  ```json
  {
    "type": "Redis",
    "settings": {
      "InstanceAddress": "localhost:5002",
      "InstanceName": "registry"
    }
  }
  ```

Default: `null`.

### ClearCacheInterval

Not used at present: no part of Registry reads it. When it is set it must be at least 1 minute
(the check refuses a smaller value). Default: `01:00:00`.

### ThumbnailsCacheExpiration

How long a thumbnail stays in the cache. At least 1 minute. Default: `00:30:00`.

### TilesCacheExpiration

How long a tile stays in the cache. At least 1 minute. Default: `00:30:00`.

### DatasetVisibilityCacheExpiration

How long the visibility of a dataset stays in the cache. At least 1 minute; when the key is missing the
cache uses its own default of 30 minutes (a new file has one day). Each Registry process
also keeps a visibility it has read in memory for
[`DatasetLookupCacheExpiration`](#datasetlookupcacheexpiration), so the access check of a request
(for example each point cloud range request) needs no cache round trip. A change made through this
Registry process takes effect at once; other processes see it when their copy expires. Default:
`1.00:00:00` (1 day).

### AuthorizationCacheExpiration

How long Registry reuses what it knows about a user for access checks: whether the user exists,
has the admin role or is deactivated. Without it, every request (each tile, thumbnail and point
cloud range request) reads these facts from the identity database again. Role changes,
deactivations and deletions made through Registry take effect at once; the expiration only bounds
changes made elsewhere (another Registry process that shares the database, direct database edits).
`00:00:00` turns the cache off. Default: `00:00:30`.

### DatasetLookupCacheExpiration

How long Registry reuses the database record of a dataset (with its organization and the members
of the organization) when it resolves `/orgs/{org}/ds/{ds}` routes. Without it, an upload of 40
files reads the same record 40 times. Changes saved by this Registry process take effect at once;
the expiration only bounds changes made elsewhere (a processing node, direct database edits).
`00:00:00` turns the cache off. Default (built in): `00:00:30`.

## Uploads & sharing

### MaxRequestBodySize

The largest upload request, in bytes. A larger request gets `413 Payload Too Large` before any byte
is stored. The limit applies to the dataset upload (`/orgs/{org}/ds/{ds}/obj`) and to the share
upload (`/share/upload/{token}`). `null`: no limit. Example: `21474836480` (20 GiB). Default: `null`.

Behind a reverse proxy, also raise or remove the limit of the proxy and turn off its request
buffering, so that Registry applies the limit. See
[Tuning the reverse proxy for large uploads](/self-hosting/troubleshooting.mdx#tuning-the-reverse-proxy-for-large-uploads).

### BatchTokenLength

The length of the token that the share endpoint makes. At least 8. Default: `32`.

### RandomDatasetNameLength

The length of the random dataset name that the share endpoint makes. At least 8. Default: `16`.

### UploadBatchTimeout

The longest time between two uploads of a share batch. At least 1 minute. Default: `01:00:00`.

### MaxZipMemoryThreshold

Removed. Folder and multi-file downloads are streamed as the ZIP archive is written. Registry
ignores the key if it is still in the file.

### MaxExportSizeBytes

The largest estimated size of a GeoTIFF raster export, in bytes. The estimate is the number of
pixels that have a value × 4 bytes, with no compression factor (for a window of the map, the pixels
in it × the share of the file that has values). The server gives the estimate and this limit to Hub
(`estimatedExportBytes` and `exportLimitBytes` of the raster value info), and a larger export is
refused. `null`: no limit. Default: `1073741824` (1 GiB).

### MaxWcsCoverageSizePixels

The largest output of a WCS `GetCoverage` (WCS 1.0, 1.1 and 2.0), in pixels on its longest side.
`GetCoverage` returns the native size of the raster or of the requested area, so a request above
the limit is an OGC exception that states it (never a smaller image); the client asks for a subset
or a smaller size. At least 1. Default: `8192`. The WMS keeps its own limit of 4096 pixels. The
value is in `GET /sys/features` as `maxWcsCoverageSizePixels`, and Hub uses it for the sample
`GetCoverage` of the Share window. The Admin page shows it as **Max WCS Coverage Size**, in the **Export & Zip** section.

### Uploads

Tuning of the upload pipeline (`POST …/obj`, bundles and chunked uploads). Every field is optional.

| Field | Default | Description |
|-------|---------|-------------|
| `ThumbnailPrecomputeWorkers` | `2` | Background workers that make the thumbnails of uploaded images in advance. A thumbnail that is not made in advance is made when it is first shown. |
| `ThumbnailPrecomputeCapacity` | `256` | Thumbnails that wait for a worker. When the queue is full, more uploads skip this step. |
| `InvalidationWindowMs` | `2000` | How long the OGC and dataset-thumbnail cache invalidations of an upload burst are collected before they run once for the whole burst. |
| `QuotaWindowSeconds` | `10` | How long one storage-use calculation serves the uploads of a user. The sizes of the uploads in between are added to it, so the quota still holds. |
| `ReceiptHours` | `24` | How long the result of an upload can be asked for by its `X-Upload-Id`. |
| `MaxPartsPerRequest` | `64` | Most file parts in one bundled upload request. |
| `MaxChunkBytes` | `134217728` (128 MB) | Largest chunk of a chunked (resumable) upload. |

The chunks of a chunked upload that nobody finishes stay for 7 days after the last chunk, so a user can resume after a reload; the cleanup then removes them. This is not a setting. A session without a file id (made before the update) and the chunks of a share batch go after 24 hours. The chunks of the open uploads of the owner of an organization count in the storage quota of that owner.

### IndexQueue

Tuning of the queue that writes new files into the index of each dataset. Every field is optional.

| Field | Default | Description |
|-------|---------|-------------|
| `BatchWindowMs` | `20` | How long the queue waits for more files before it commits a batch. |
| `MaxBatchSize` | `64` | Most paths in one batch. |
| `QueueCapacityPerDataset` | `512` | Files that can wait for one dataset before new uploads wait. |
| `EnqueueTimeoutSeconds` | `120` | How long a request waits for a place in the queue before it fails with a temporary error. |
| `IdleLaneTrimSeconds` | `1800` (built in) | Seconds the queue of an idle dataset is kept in memory. From 1 to 86400. |

### Reconciliation

Tuning of the hourly index reconciliation ([`IndexReconciliationCron`](#indexreconciliationcron)).

| Field | Default | Description |
|-------|---------|-------------|
| `MaxItemsPerRun` | `500` | Most files that are not in the index and are queued again, per dataset and run. |
| `QuarantineRetentionDays` | `7` | Days a quarantined file is kept before it is deleted. |

## Downloads

### MaxConcurrentDownloadsPerUser

The most downloads at the same time per user (per IP address for anonymous users). `null`, `0` or
a negative number: no limit (no check refuses it). Default: `null`.

### DisableAnonymousBulkDownloads

When `true`, anonymous users cannot download archives: a whole dataset, a folder or a selection of
files. They can still download single files. Signed-in users are not affected. The anonymous
`/sys/features` answer has this flag, so the Hub hides the actions. Default: `false`.

## Users & organizations

### DefaultAdmin

The administrator that Registry creates on the first start (local accounts only). `Email`,
`UserName` and `Password` are required. A later change of `Password` does not change the password
of the existing account: use **My Account**, or
[`--reset-admin-password`](/self-hosting/troubleshooting.mdx#reset-the-administrator-password).

```json
"DefaultAdmin": {
  "Email": "admin@example.com",
  "UserName": "admin",
  "Password": "password123"
}
```

### EnableStorageLimiter

Limits the storage of each user to the `maxStorageMB` value of the user's metadata. A user without
the value has no limit. See [Storage quotas](/self-hosting/users.mdx#storage-quotas). Default: `false`.

### EnableDefaultUserOrganization

When `true`, Registry creates a personal organization for each new user, with the user name as
slug. Set it to `false` when administrators assign organizations. Default: `true`.

```bash
AppSettings__EnableDefaultUserOrganization=false
```

### EnableOrganizationMemberManagement

When `true`, the owner of an organization, its members with the **Admin** permission and the
server administrators can add and remove its members in the Hub (**Members** on the datasets page of
the organization, **Manage members** on the Organizations page). When `false`, nobody can, server
administrators included: the buttons do not show and the member endpoints answer `403`. Default: `false`.

### PasswordPolicy

The rules for new passwords. `null` turns them off.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `MinLength` | `int` | `8` | Minimum length |
| `RequireDigit` | `bool` | `true` in a new file; `false` when the key is missing | At least one digit |
| `RequireUppercase` | `bool` | `false` | At least one uppercase letter |
| `RequireLowercase` | `bool` | `false` | At least one lowercase letter |
| `RequireNonAlphanumeric` | `bool` | `false` | At least one character that is not a letter or a digit |

```json
"PasswordPolicy": {
  "MinLength": 12,
  "RequireDigit": true,
  "RequireUppercase": true,
  "RequireLowercase": true,
  "RequireNonAlphanumeric": true
}
```

## Networking

### AllowedOrigins

The origins allowed by CORS. `null` or empty: all origins. Restrict it to the origins that need
access. Default: `null`.

```json
"AllowedOrigins": [ "https://hub.example.com", "https://admin.example.com" ]
```

### ExternalUrlOverride

The public URL of Registry, for example `https://registry.example.com`. It must be an absolute URL.
E-mails, links and the update check use it. Set it when Registry runs behind a reverse proxy.
Default: `null`.

### KnownProxies

IP addresses of the reverse proxies whose `X-Forwarded-For` and `X-Forwarded-Proto` headers Registry
trusts. A value replaces the default: list loopback too if the proxy also connects over it. An
address that is not valid stops the start. See [Reverse proxy](/self-hosting/production.mdx#reverse-proxy).
Default: `["127.0.0.1", "::1"]`.

### KnownNetworks

Networks (CIDR) whose addresses Registry trusts as reverse proxies, in addition to `KnownProxies`.
Behind a port published by Docker, the peer is the bridge gateway (`172.x.0.1`): the production
template sets `[ "172.16.0.0/12" ]`. A network that is not valid stops the start. Default: `[]`.

### Security headers

Registry adds these headers to every response. There is nothing to configure.

| Header | Value |
|--------|-------|
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `SAMEORIGIN` (left out for embed URLs with `?embed=1`) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |

## E-mail

### Smtp

The outgoing mail server. E-mail is off by default: while `Enabled` is `false`, Registry writes each
e-mail to the log and drops it. When `Enabled` is `true`, `Host` and `FromAddress` are required, and
`UserName` and `Password` must be set together (or both left empty). See
[E-mail (SMTP) & templates](/self-hosting/email.mdx).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `Enabled` | `bool` | `false` | Sends e-mail through the server below |
| `Host` | `string` | — | Host name of the SMTP server |
| `Port` | `int` | `587` | `587` STARTTLS, `465` SSL on connect, `25` local relay |
| `Security` | `string` | `StartTls` | `StartTls`, `SslOnConnect` or `None` |
| `ValidateServerCertificate` | `bool` | `true` | Validate the certificate chain of the server (the host name is always checked) |
| `UserName` | `string` | `null` | User name of the SMTP account |
| `Password` | `string` | `null` | Password of the SMTP account. Prefer the variable `AppSettings__Smtp__Password` |
| `FromAddress` | `string` | — | Sender address |
| `FromName` | `string` | `null` | Sender name. `null`: the Hub application name (`HubOptions.AppName`, else `DroneDB`) |
| `ReplyTo` | `string` | `null` | Reply address |
| `TimeoutSeconds` | `int` | `30` | Timeout of each SMTP operation |

### BuildNotifications

How [build notification e-mails](/self-hosting/email.mdx#build-notifications) are grouped. They need `Smtp`.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `DigestMinutes` | `int` | `5` | How long Registry waits after the first build of a user ends before it sends one e-mail with every build of that user that ended in the meantime. From `1` to `60`; another value stops the start. |

## Update check

Registry asks dronedb.app once a day for new versions. See [Update check](/self-hosting/update-check.mdx) for
what it sends.

### UpdateCheckCron

When the check runs. Empty: once a day, at a time that depends on the instance. `disabled`, `off`
or `none` switches it off (nothing is sent). Any other value is a cron expression. Default: empty.

### UpdateCheckEndpoint

The address of the update check service. It must be an absolute `https` URL, or Registry does not
start. Change it only for a test service. Default:
`https://dronedb.app/wp-json/dronedb/v1/update-check`.

### UpdateCheckEmail

Which new versions are e-mailed to the administrators: `security` (only versions with security
fixes), `all` or `off`. It needs `Smtp`. Another value stops the start. Default: `security`.

## Processing & resources

### WorkerThreads

The minimum number of worker threads of the process. `0` or less: the .NET default. When set, it
is also the default number of light background workers
([`ProcessingBudget:LightWorkers`](#processingbudget)). Default: `-1`.

### NativeConcurrency

How many native renders run at the same time in one Registry process. Requests over the limit wait
for a free slot (and stop waiting when the client goes away), so a burst of tiles or thumbnails
cannot take every core.

```json
"NativeConcurrency": { "Tiles": 0, "Heavy": 0 }
```

| Field | Default | Description |
|-------|---------|-------------|
| `Tiles` | `max(2, cores / 2)` | Map tiles and map renders (WMTS, WMS, OGC API tiles) |
| `Heavy` | `max(1, cores / 4)` | Thumbnails and coverage renders (WCS) |

`0` or less: the default. The gauge `registry.native.in_flight` (meter `Registry.NativeWork`, tag
`lane`) reports the renders that run in each lane.

### HostBudget

The Registry processes that share the machine. When they are declared, each process takes its
share of the cores and memory (its weight over the sum of the weights) for its background workers,
its render lanes and the CPU pool of the DroneDB library.

```json
"HostBudget": { "WebServers": 1, "ProcessingNodes": 2 }
```

| Field | Default | Description |
|-------|---------|-------------|
| `WebServers`, `ProcessingNodes`, `ThumbnailGenerators` | `0` | Processes of each kind on the machine (`0`: not declared) |
| `Cores` | `0` | Logical processors of the machine (`0`: those the process sees) |
| `MemoryMb` | `0` | Memory of the machine in MiB (`0`: what the process sees) |
| `WebServerWeight`, `ProcessingNodeWeight`, `ThumbnailGeneratorWeight` | `1`, `2`, `1` | Share of each kind of process. Greater than 0. |
| `IoThreads` | `0` | Disk-bound threads for the whole machine, split like the cores (`0`: the library default, 4 per process) |

With nothing declared, each process plans the whole machine. The production Compose file sets
`AppSettings__HostBudget__WebServers=1` and `AppSettings__HostBudget__ProcessingNodes=2`. **Admin →
Configuration** shows the effective budget.

### ProcessingBudget

The concurrency and native resources of background jobs. Native builds run on their own queue.
`0` (or missing): derived from the host, or from the host budget when it is declared.

| Field | Default | Description |
|-------|---------|-------------|
| `HeavyWorkers` | derived | Jobs that run native builds at the same time (COG, COPC, bm3d, LOD, raster tools) |
| `LightWorkers` | derived | Other jobs at the same time (imports, exports, clean-up, thumbnails, scheduling) |
| `BuildThreads` | derived | Threads of one native build (`DDB_BUILD_THREADS`): GDAL threads in a raster build, `bm3d` threads in a 3D model build |
| `BuildCacheMb` | `1024` | GDAL block cache of a raster build, in MB (`DDB_COG_CACHE_MB`). `0` or missing: `1024` |
| `BuildWarpMemoryMb` | `512` | GDAL warp memory of a raster build, in MB (`DDB_WARP_MEMORY_MB`). `0` or missing: `512` |
| `BackgroundRebuildThreads` | `2` | Threads of each [background rebuild](#artifactcompletenesscheckercron) (`0` or missing: the default). It caps `BuildThreads` and never raises it. It does not follow the size of the host. |

### Ddb

A top-level section (next to `AppSettings`) with the process settings that Registry passes to the
DroneDB library before it starts it. A value that is left out is not sent: the library uses its
environment variable or its default. `CacheDir` is the exception: Registry always sends it. See
[DroneDB library](/docs/developers/library).

```json
"Ddb": { "CpuPoolSize": 6, "GdalCacheMb": 512 }
```

| Field | Range | When left out | Description |
|-------|-------|---------------|-------------|
| `CpuPoolSize` | 0 to 4096 | `DDB_CPU_POOL_SIZE` when it is set; else, when a host budget is declared, the cores of the process − 1; else cores − 1 | Worker threads the library may run beside the calling threads |
| `IoThreads` | 1 to 256 | `DDB_IO_THREADS` when it is set; else, when `HostBudget:IoThreads` is above 0, the share of the process; else 4 | Threads of one disk-bound step (hashing, deleting build folders) |
| `MinFreeDiskMb` | 0 or more | `DDB_MIN_FREE_DISK_MB` or 512 | Free MiB a build needs on the volume it writes to; `0` turns the check off |
| `GdalCacheMb` | 16 to 1048576 | `DDB_GDAL_CACHE_MB` or 1024, as an upper bound | Size of the GDAL block cache in MiB, shared by the whole process. When set, it is the size of the cache (it wins over `GDAL_CACHEMAX`). Each process on a host has its own cache: size it for the role. |
| `CacheDir` | absolute path | `<TempPath>/ddb-cache` | Where the library caches thumbnails, tiles, index templates and DSM tiles |

A value here wins over the host budget and the environment variables. Registry logs the effective
values at start.

### RemoteThumbnailGeneratorUrl

The URL of a thumbnail generator (a Registry with instance type `3`). `null`: the web server makes
the thumbnails. Default: `null`.

### ThumbnailGeneratorToken

The shared secret of the web server and the thumbnail generator, sent in the `X-Thumbnail-Token`
header. Registry generates it on the first start when it is empty. A thumbnail generator refuses to
start without it; both read the same `appsettings.json`.

### DefaultThumbnailSize

The size of a thumbnail in pixels when the request gives none (for example `GET …/thumb?path=`).
Default: `512`.

### DatasetThumbnailCandidates

File names in the root of a dataset that Registry checks, in order, for the thumbnail of the
dataset. The first match is used. Default:
`["thumbnail.webp", "thumbnail.jpg", "thumbnail.png", "cover.webp", "cover.jpg", "cover.png"]`.

**Limits and quotas:**

| Field | Default | Description |
|-------|---------|-------------|
| `MaxConcurrentTasksPerUser` | `3` | Tasks of one user that run at the same time |
| `MaxQueuedTasksPerUser` | `20` | Tasks of one user that are not finished |
| `MaxConcurrentTasksPerOrg` | `10` | Tasks of one organization that run at the same time |
| `MaxConcurrentTasksGlobal` | `32` | Tasks that run at the same time on the whole Registry |
| `MaxEstimatedOutputBytesPerSubmit` | `21474836480` (20 GiB) | Largest estimated output of one task |

**Logs and progress:**

## Scheduled jobs

Every cron key follows the same rules:

- **Missing or empty**: the built-in schedule of the job.
- **`disabled`, `off` or `none`** (any case): the job is removed from Hangfire.
- **Any other value**: a cron expression, used as written.

The default schedules:

| Key | Default |
|-----|---------|
| [`CleanupExpiredJobsCron`](#cleanupexpiredjobscron) | `0 0 * * *` (daily, at midnight) |
| [`SyncJobIndexStatesCron`](#syncjobindexstatescron) | `0 * * * *` (hourly) |
| [`RecoverIndexedJobPublicationsCron`](#recoverindexedjobpublicationscron) | `* * * * *` (every minute) |
| [`ProcessPendingBuildsCron`](#processpendingbuildscron) | `0 */6 * * *` (every 6 hours) |
| [`DatasetCleanupCron`](#datasetcleanupcron) | `0 0 * * *` |
| [`ArtifactCompletenessCheckerCron`](#artifactcompletenesscheckercron) | `0 2 * * *` |
| [`OrphanedDatasetCleanupCron`](#orphaneddatasetcleanupcron) | `0 3 * * *` |
| [`JobIndexCleanupCron`](#jobindexcleanupcron) | `0 4 * * *` |
| [`IndexReconciliationCron`](#indexreconciliationcron) | `0 * * * *` (hourly) |
| [`UpdateCheckCron`](#updatecheckcron) | once a day, at a time that depends on the instance |

A new `appsettings.json` leaves out `CleanupExpiredJobsCron`, `SyncJobIndexStatesCron` and
`ProcessPendingBuildsCron`, so their defaults apply. An `appsettings.json` from an earlier version
can still set them (`0 * * * *`, `*/5 * * * *` and `* * * * *`): the value in the file wins.
Remove those keys to use the defaults.

### CleanupExpiredJobsCron

The job that deletes expired Hangfire jobs.

### SyncJobIndexStatesCron

The job that corrects the job index. Job states are written as they change; this job only fixes
entries that missed a change (for example across a restart).

### RecoverIndexedJobPublicationsCron

The job that completes jobs whose publication stopped before they could run (for example a restart
right after the job was created). Such jobs wait in the `Indexing` state and are published with
their original id; a job with an unusable record is cancelled.

### ProcessPendingBuildsCron

The job that processes pending builds. It starts the automatic retries again for builds that failed
for a temporary reason (for example no disk space or a tool timeout), also after their retries gave
up or were lost in a restart. A build that waits for a missing file is not retried on a timer: it
runs at once when a file with that name is uploaded or moved into the dataset. This job also starts
the builds whose missing file arrived in another way.

### OrphanedDatasetCleanupCron

The job that deletes dataset folders that have no database entry (for example after a failed
delete).

### DatasetCleanupCron

The job that runs the DroneDB clean-up on every dataset of every organization: it removes stale
entries and unused build files. `POST /sys/cleanup` (administrators) runs the same operation once.
The job also deletes what interrupted uploads leave in a dataset when nothing was written to it for
24 hours: push folders that were never committed (`.ddb/tmp/push-*`) and temporary upload files
(`.uploads/*.tmp`).

### ArtifactCompletenessCheckerCron

The job that checks every buildable entry of every dataset and queues a build for each entry whose
built files are missing or empty. It brings old datasets to a new build format (for example EPT to
COPC, or Nexus to bm3d). `POST /sys/check-artifact-completeness` (administrators) runs it once.

An entry whose build has only files of an older layout (a 3D model with only the Nexus file
`nxs/model.nxz`, from before bm3d) goes to the background `rebuilds` queue, not to the queue of the
builds that users wait for. That queue has its own Hangfire server with **one worker**, and each
rebuild uses at most [`ProcessingBudget:BackgroundRebuildThreads`](#processingbudget) threads. So the
first check after an upgrade rebuilds the old models one after the other without slowing user
builds. An entry that already has a build job is skipped. Until a rebuild writes `bm3d/`, the model
stays viewable from `nxs/` in the previous viewer. A failed rebuild keeps it; a temporary failure
is retried like a build and stays a background rebuild. See [Upgrading](/self-hosting/upgrading.mdx#3d-models-nexus-to-bm3d).

### JobIndexCleanupCron

The job that deletes old finished records (Succeeded, Failed, Deleted) from the `JobIndices` table.
The same job deletes sent build notifications older than 30 days (it keeps the record of a build
that still waits for files) and sends the notifications that waited for more than one hour (see
[Build notifications](/self-hosting/email.mdx#when-an-e-mail-is-sent)). `POST /sys/cleanup-jobindices`
(administrators) runs it once; the optional `retentionDays` query parameter overrides the
retention for that run.

### IndexReconciliationCron

The job that compares the index of each dataset with its files: it queues again the files on disk
that are not in the index, reports (never deletes) indexed entries whose file is missing, and
deletes quarantined files after their retention. See [`Reconciliation`](#reconciliation).

### JobIndexRetentionDays

Days a finished record of the job index is kept. Default: `60`.

```json
"JobIndexRetentionDays": 30,
"JobIndexCleanupCron": "0 2 * * *"
```

### HangfireJobRetentionDays

Days a finished Hangfire job record (not failed) is kept. A value below 1 is read as 1. Low values
keep the MySQL tablespace small. Default: `2`.

### HangfireInvisibilityTimeoutHours

MySQL job store only. The hours a running job counts as active (a value below 1 is read as 1). After that, the store treats it as
abandoned and another worker can start it again, which collides with the build lock of DroneDB.
Raise it if a build can take longer (a large point cloud, mesh or orthophoto). No effect with
`HangfireProvider` `InMemory`. Default: `4`.

## Import

Section `AppSettings:Import`: imports from URLs and from other Registry servers, and the file types
that every write path accepts. Every field is optional.

**Size and sources:**

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `MaxImportSizeBytes` | `long` | `0` (no limit) | Largest import task, in bytes |
| `MaxFileImportSizeBytes` | `long` | `0` | Largest single file of a URL import (`import-file`). `0`: `MaxImportSizeBytes` applies |
| `AllowedSourceTypes` | `string[]` | `null` (all) | Allowed sources of a dataset import: `registry`, `archive-url` |
| `MinDownloadSpeedBytesPerSec` | `long` | `1024` | A URL import that stays slower than this for `LowSpeedGraceSeconds` stops. `0` turns the check off |
| `LowSpeedGraceSeconds` | `int` | `30` | The window of the speed check, and the longest wait for one read |

**File types:** these two lists apply to **every way a file enters a dataset**: URL import
(`import-file`), archive extraction (`archive-extract`), archive URL import (`archive-url`), Hub
upload, `ddb push` and transfer between datasets. Matching ignores case and the leading dot.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `BlockedFileExtensions` | `string[]` | executables and scripts | Extensions that are refused. Ignored when `AllowedFileExtensions` is not empty. |
| `AllowedFileExtensions` | `string[]` | `[]` | When not empty, **only** these extensions are accepted (a file without an extension is refused too) |

The built-in block list: `.exe`, `.dll`, `.so`, `.dylib`, `.bat`, `.cmd`, `.com`, `.msi`, `.msix`,
`.appx`, `.ps1`, `.psm1`, `.psd1`, `.vbs`, `.vbe`, `.js`, `.jse`, `.wsf`, `.wsh`, `.hta`, `.sh`,
`.bash`, `.zsh`, `.ksh`, `.csh`, `.run`, `.elf`, `.scr`, `.pif`, `.cpl`, `.gadget`, `.jar`, `.apk`,
`.app`, `.deb`, `.rpm`, `.py`, `.pyc`, `.pyo`, `.rb`, `.pl`, `.php`, `.lnk`, `.reg`, `.command`,
`.workflow`. An archive skips the refused files and extracts the rest. An upload, a push or a
transfer with a refused file fails with a message that names the file and the reason.

**Network safety (SSRF):**

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `SsrfAllowPrivateNetworks` | `bool` | `false` | Allows imports from loopback, link-local and private addresses (10.x, 172.16–31.x, 192.168.x). Only in trusted networks. |
| `SsrfAllowedHosts` | `string[]` | `[]` | Host names that may resolve to such addresses (for example a Registry on your internal network). Public hosts are always allowed. |

**HTTP:**

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `MaxRedirects` | `int` | `5` | Most redirects followed. Each one is checked again by the SSRF rules. |
| `ConnectTimeoutSeconds` | `int` | `30` | Timeout of the connection to a source |
| `TransferTimeoutSeconds` | `int` | `3600` | Timeout of the whole transfer |
| `RegistryDownloadConcurrency` | `int` | `4` | Files downloaded at the same time from a source Registry. Lower it for a source that throttles (HTTP 429). |

```json
  "SsrfAllowedHosts": [ "registry.internal.example.com" ],

}
```

## Logging

The top-level `Serilog` section. A new file logs at `Warning` to the console and to
`logs/registry.txt` in the storage folder. The default instance (type `0`) keeps that name. The
other instance types add a suffix to it (`registry-web`, `registry-node-<host name>`,
`registry-thumbs`). Files roll daily, with the date in the name (`registry20261108.txt`); 14 are
kept, at most 100 MB each.

To change the level, change the value of the level switch and restart:

```json
"Serilog": {
  "LevelSwitches": { "$controlSwitch": "Information" },
  "MinimumLevel": { "ControlledBy": "$controlSwitch" }
}
```

Levels: `Verbose`, `Debug`, `Information`, `Warning`, `Error`, `Fatal`.
