Administrators manage the accounts of a Registry in the Hub, on the **User Management** page. To do
the same through the REST API, see [Users & organizations API](/docs/developers/users-api).

<Screenshot id="self-hosting/users--list" />

## Open the page

1. Sign in as an administrator.
2. Open the user menu (your user name, top right), then click **Manage Users**.

<Screenshot id="self-hosting/admin-pages--menu" />

The page shows every user with the **Username**, **Email**, **Roles**, **Organizations**,
**Datasets**, **Storage** (used and quota) and **Created** columns. On a phone, each user is a card
with every value and the actions on one line. The page shows as many users as fit the height of the window (**N (fit)** in the paginator); you can choose another number. Type in **Search users** to filter the list; click **Refresh** to load it again.

:::note When the page is missing

**Manage Users** is shown only when Registry manages the accounts itself. With
[LDAP](/self-hosting/ldap.mdx) or an external authentication service (`ExternalAuthUrl`), the directory
manages users, passwords and the admin role, and the Hub hides the page.

:::

## The first administrator

The first start creates the administrator of the [`DefaultAdmin`](/self-hosting/configuration.mdx#defaultadmin)
setting: `admin` / `password123` (a Docker Compose install takes the password from
`REGISTRY_ADMIN_PASSWORD`). Change the password at once in **My Account**. The **Delete User**
button is always disabled for the user `admin`.

## Add a user

<Steps>

1. Click **New User**.

   <Screenshot id="self-hosting/users--add" />

2. Enter the **Username**, the **Email** and the **Password**, and type the password again in **Confirm
   Password**. A user name is 1 to 127 lowercase letters (`a-z`) and digits. The dialog lists the rules of
   the [password policy](/self-hosting/configuration.mdx#passwordpolicy) under the password field from the
   start and ticks each one as you type. A message under a field says what is wrong with it.
3. Optional: choose one or more **Roles**.
4. Click **Add User**.

</Steps>

When [`EnableDefaultUserOrganization`](/self-hosting/configuration.mdx#enabledefaultuserorganization) is on
(the default), the new user also gets a personal organization with the user name as slug.

## Edit a user

In the **Actions** column:

- **Edit User** (pencil): change the **Email** and the **Roles**, then click **Update User**. The e-mail is
  checked at the field as you type, and a refusal shows once, at the field or in the window. Clear it to
  remove the address (it is optional, though build notification e-mails need one). The user name cannot
  change. Users cannot change their own e-mail address in the Hub: an
  administrator sets it here. Build notification e-mails need a valid address.
- **Change Password** (key): enter the **New Password** twice and click **Change Password**. Leave
  **Current Password** empty to set a password without knowing the old one. The dialog lists the password
  rules and says under the field which one the new password breaks. The dialog asks the browser not to
  fill in a saved password.
- **Disable User** / **Enable User**: Disable asks first, then blocks sign-in at once; the open
  sessions of the user lose access too. The data of the user is kept. A disabled user has a
  **Disabled** tag next to the user name. Enable gives the access back. You cannot disable your
  own account or the last active administrator.

Edit User changes only the roles that you add or remove. It never disables or enables a user.

## Delete a user

1. Click **Delete User** (trash can).
2. Optional: in **Transfer data to successor**, choose the user who gets the organizations and
   datasets. Without a successor, every organization, dataset and file of the user is deleted.
3. With a successor, choose what happens when a dataset name already exists in the successor's
   organizations: **Rename conflicting datasets**, **Overwrite existing datasets** or **Stop if
   conflict detected**.
4. Click **Delete**.

<Screenshot id="self-hosting/users--delete" />

The **User Deleted Successfully** window lists the organizations and datasets that were
transferred or deleted, and the share batches that were deleted.

## Roles

Click **Manage Roles** to open **Role Management**. The **View Roles** tab lists the roles: click
**Delete** next to a role to delete it. The system roles have a **System Role** tag instead. On
the **Add Role** tab, enter a **Role Name** and click **Add Role**. A role name follows the rule of the user
names: 1 to 127 lowercase letters (`a-z`) and digits, which the tab shows under the field. A role created
earlier with another name, for example one with a `/` in it, keeps working and can be deleted.

<Screenshot id="self-hosting/users--roles" />

| Role | Meaning |
|------|---------|
| `admin` | Instance administrator: every organization and dataset, the admin pages, Hangfire. A system role: it cannot be deleted. |
| `deactivated` | Blocks sign-in. A system role: it cannot be deleted, and only **Disable User** and **Enable User** change it. The role pickers do not offer it. |
| Other roles | Labels you create. They give no rights by themselves. Use them in [tool gating](/self-hosting/processing-nodes.mdx#tool-gating) (`AllowedRoles`) to allow a tool for some users only. |

Assign roles to a user with **Edit User**. Remove a role from every user before you delete it.

## Organizations of a user

Click the number in the **Organizations** column of a user to open **Manage User Organizations**.

<Screenshot id="self-hosting/users--organizations" />

- To add the user to an organization, choose the **Organization** and the **Permissions**, then
  click **Add**.
- To change the permissions in an organization, choose another value in its row. The change is
  saved at once.
- To remove the user from an organization, click **Remove**.

| Permissions | The member can |
|-------------|----------------|
| **Read Only** | Read the datasets of the organization |
| **Read/Write** | Also write: upload, change and build files (the default) |
| **Read/Write/Delete** | Also delete |
| **Admin** | Also manage the members of the organization |

## All organizations

Click **Manage Organizations** to open **Organization Management**. It lists every organization of
the Registry.

- To create an organization, enter the **Organization Name** (the **Organization Slug** is
  suggested from it) and an optional **Description**, then click **Create Organization**.
- To delete an organization, click **Delete** in its row and confirm. **Every dataset of the
  organization is deleted.** The `public` organization cannot be deleted.

Owners and members manage their own organizations on the Organizations page of the Hub: see
[Dataset members & organizations](/docs/hub-guide/datasets/members). By default only
administrators add and remove members. With
[`EnableOrganizationMemberManagement`](/self-hosting/configuration.mdx#enableorganizationmembermanagement),
owners and members with the **Admin** permission manage members (**Members** button).

A **Public** organization can be read by anyone, signed in or not, and every signed-in user sees
it in the Organizations list. Those who are not members can only read it, and its private
datasets stay hidden.

## Storage quotas

1. Turn on [`EnableStorageLimiter`](/self-hosting/configuration.mdx#enablestoragelimiter) and restart
   Registry.
2. Give each user a quota in MB with the `maxStorageMB` key of the user's metadata. The Hub has no
   field for it: use the API (`POST /users/{userName}/meta`, see
   [Users & organizations API](/docs/developers/users-api)).

The **Storage** column then shows the use, the quota and a bar. A user without `maxStorageMB` has
no limit. When a user is at the quota, new uploads are refused.

The quota is the one of the **owner of the organization**, and it counts on every way that adds files to its datasets:
uploads (also chunked and bundled), push, paste and copy, file and dataset import, archive extract,
Merge Multispectral, Align, Mask Borders and photogrammetry. A member who writes into the organization of an
owner who is over the quota gets `507` (**Storage quota exceeded**), and the message says how much the owner has left.
An administrator owner has no limit, and an organization without an owner is unlimited.

A task that adds files is refused when it starts, and when it is retried, if nothing is left or its estimate does not fit.
While it runs it also reads what is left when it writes. If the quota stops the task, the task fails with the `507` text, and
Registry removes the files that it added and puts back the files it replaced. The parts of the open chunked uploads of the
owner count in the use: **Cancel** or **Discard** in the upload window of the Hub, or the cleanup after 7 days, frees them.

## Common problems

| Problem | What to check |
|---------|---------------|
| No **Manage Users** in the user menu | You are not an administrator, or LDAP or external authentication is on. |
| A quota has no effect | `EnableStorageLimiter` is `true`, the user has `maxStorageMB`, and the value is a number. |
| A role cannot be deleted | `admin` and `deactivated` are system roles. |
| A user cannot sign in | The user has the **Disabled** tag: click **Enable User**. |
| **Disable User** is refused | You cannot disable your own account or the last active administrator. Make another user an administrator first. |
| A new user or an e-mail change is refused | The user name must be lowercase letters and digits only; the e-mail must be one valid address. |
