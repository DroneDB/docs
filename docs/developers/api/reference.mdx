## The full reference

Every Registry serves its own interactive API reference, generated from its code:

| What | Where |
|---|---|
| Interactive reference (Scalar) | `/scalar/v1`, for example [hub.dronedb.app/scalar/v1](https://hub.dronedb.app/scalar/v1) |
| OpenAPI document | `/swagger/v1/swagger.json` |

The reference of a Registry always matches its version. Use it for the list of endpoints, the
parameters and the response fields. It lists the `bearer` and `basic` security schemes (the
Authentication section of Test Request), the `401` and `403` answers of the protected endpoints
and the `multipart/form-data` fields of the upload endpoints. This page holds the rules that apply
to all endpoints.

## Requests

- **Routes.** An organization is `/orgs/{orgSlug}`, a dataset `/orgs/{orgSlug}/ds/{dsSlug}`.
  Files, builds, tasks, metadata and the OGC services of a dataset are below that. System and
  administration endpoints are below `/sys`, users below `/users`.
- **Slugs** have 2 to 128 characters: lowercase letters, digits, `_` and `-`. They start with a
  letter or a digit and have no `--`. A refused slug answers `400` with the rule.
- **Bodies.** Many endpoints read form fields (`multipart/form-data` or
  `application/x-www-form-urlencoded`): sign-in, datasets, organizations, uploads, builds,
  search. Newer endpoints read JSON: tasks, imports, preferences, members, users. The reference
  says which one each endpoint takes.
- **Dataset paths** (`path`) are relative to the root of the dataset, with `/` or `\` as the
  separator. An absolute path, a `..` segment, the reserved `.ddb` folder or a path that is not
  valid UTF-8 is refused with `400`.
- **Enumerations** are numbers in JSON: dataset visibility `0` private, `1` unlisted, `2`
  public; organization permissions `0` read only, `1` read and write, `2` read, write and
  delete, `3` admin. Entry types are numbers too:
  see [entry types](/docs/reference/formats#entry-types).
- **Times.** Index values (`mtime`) and token expiry (`expires`) are Unix seconds. Database
  records (`creationDate`, `lastModified`) are ISO 8601 dates.
- **Cancellation.** A request whose client disconnects stops its work and gets no answer. The
  server logs it as `499`.

## Errors

Errors are RFC 9457 `ProblemDetails` with the media type `application/problem+json`:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.4",
  "title": "Forbidden",
  "status": 403,
  "detail": "The current user is not allowed to read this dataset",
  "traceId": "00-…",
  "noRetry": true
}
```

- Every error has this shape, also a `401` from a protected endpoint, a `403` from an
  administrator-only endpoint (`/sys`, `/health`, `/hangfire`) and a `507`. Show `detail` to the
  user.
- `noRetry: true` means that the same request will fail again. Do not retry it.
- Validation errors of a body are `ValidationProblemDetails`: an `errors` object per field and
  the joined messages in `detail`.
- Before Registry 3.0 the body was `{"error": "…"}`. A client that also talks to older servers
  falls back to `error`.

| Status | Meaning |
|---|---|
| `400` | Invalid parameters, or an uploaded file that cannot be read as its file type (for example a `.laz` that is not LAZ; `noRetry: true`, the detail names the file) |
| `401` | Not signed in, or the token is no longer valid. The body is `ProblemDetails` with `detail` "Not signed in", and the answer has `WWW-Authenticate: Bearer`. `GET /orgs` without a token answers its own `401` ("Invalid user"). |
| `403` | Signed in without permission (a `401` before Registry 3.0). Admin-only endpoints say "Only administrators can perform this operation". |
| `404` | Not found, also for a request other than `GET` or `HEAD` to a path that no endpoint answers |
| `409` | Conflict |
| `413` | Too large (`noRetry: true`) |
| `429` | Too many requests: the concurrent download limit or a rate limit. Read `Retry-After`. |
| `500` | Server error |
| `503` | Temporary: a busy index, a build that holds it, a server that stops. Read `Retry-After` and try again. |
| `507` | The storage quota of the organization owner is full. An upload, a chunk, a commit, a push, a paste or copy, an import and the start or the retry of a task that adds files answer `type` `https://www.rfc-editor.org/rfc/rfc4918#section-11.5` and `title` "Insufficient Storage". The `detail` says how much the owner has left |

The OGC services answer with the exception format of their standard instead: see
[OGC errors](/developers/ogc.mdx#errors).

## Paging

| Endpoint | Parameters | Total |
|---|---|---|
| `GET /orgs/{orgSlug}/ds` | `skip`, `take` (at most 500), `q` (search in name, slug and tagline), `sort` (`name`, `creationDate`, `lastModified`, `entries`, `size`, `visibility`), `desc=true`, `slugs` (a comma-separated list) | `X-Total-Count` header |
| `GET …/tasks`, `GET /sys/tasks` | `skip`, `take` (at most 200), `toolId`, `state`; `/sys/tasks` also `userId`, `sortField` (`createdAt`, `state`, `toolId`) and `sortOrder` (`asc`, `desc`) | |
| `GET /stac/collections/{org}/{ds}/items` | `limit` (default 10, at most 10000), `offset`, `bbox`, `datetime` | `numberMatched` |
| `GET /stac/collections` | `limit` (default 10, at most 100), `offset` | |
| WFS `GetFeature` | `count` (at most 10000), `startIndex` | `numberMatched` |
| OGC API `…/items` | `limit` (at most 1000), `offset`, `bbox` | |

`GET /orgs/{orgSlug}/ds` without parameters returns every dataset. With any of them it returns
one page. `X-Total-Count` is the number of datasets that match the whole query (`q`, `slugs`, or
both), not the size of the page. `GET …/tasks` sends an `ETag`: a request with `If-None-Match` gets `304` while the
list is the same.

## Build file URLs

The build products of an entry (COG, COPC, bm3d, vector tiles, 3D Tiles, RAD) are served below
`…/build/{key}/{path}` and `…/build/{key}@{version}/{path}`. The key is the content hash of the file, or the hash and 16 characters of its georeference for a model or a Gaussian splat that has one (see [Build key](/developers/library.mdx#build-key)). Rules:

- **Read the URL from the entry.** Listings and pending builds give each entry
  `artifacts: [{role, url, mediaType, downloadName?}]`. Never compose a `/build/` path.
- **The URL holds a version.** `version` changes when a build rewrites the file under the same
  key (a forced rebuild, a newer layout). A rebuild gives the entry a new URL in the next
  listing. Treat `version` as opaque: compare it, do not parse it.
- **Caching.** When the URL names the current version, the answer is
  `Cache-Control: private, max-age=86400, immutable`. Without a version, or with a replaced
  one, it is `private, no-cache` with an `ETag`; a conditional request gets `304` while the file
  is the same. Files that the index of a directory artifact names by a relative URL (the tiles
  of a 3D Tiles `tileset.json`) get the same version.
- **Range requests** work on every build file. `HEAD` sends the headers of `GET`.
- **Media types** come from the library: COG
  `image/tiff; application=geotiff; profile=cloud-optimized`, COPC
  `application/vnd.laszip+copc`, GeoPackage `application/geopackage+sqlite3`, bm3d
  `application/vnd.dronedb.bm3d`.
- **Legacy outputs.** A model built before DroneDB 2.0 lists `model.nexus` instead of
  `model.bm3d` until the background rebuild; a point cloud built before COPC lists
  `pointcloud.ept`. A client that reads the roles in its order of preference shows the old
  output until the new one exists.

For a link that you give to a person or paste in QGIS, copy it from Hub: it changes after a
rebuild. To download a product under the name of the entry, use
`GET …/build-artifact?path=…&role=…` ([workflows](/developers/api/workflows.mdx#builds-and-build-files)).
The roles are in the [library build manifest](/developers/library.mdx#build-manifest).

## The feature catalog

`GET /sys/features` needs no sign-in. Clients read it to know what the server offers:

| Field | Description |
|---|---|
| `registryVersion`, `hubVersion`, `ddbVersion` | The versions of the backend, the web app and the DroneDB library |
| `taskTools` | The processing tools: id, version, title, required access, artifact flag, and `hidden`, `disabled`, `disabledMessage` |
| `taskStates` | The task states, each `{value, terminal}` |
| `entryTypes` | The entry types of the library: `{id, name, buildable, thumbnail, sidecarExtensions, roles}`. `thumbnail` is `none`, `file` or `build`. |
| `archiveExtensions` | The archive suffixes the server extracts, lowercase, compound ones first (`tar.gz` before `gz`) |
| `emailEnabled` | Whether the server sends e-mail. When `false`, hide what needs e-mail. |
| `userManagement`, `organizationMemberManagement` | Whether local users and organization members can be managed (`false` with external authentication) |
| `storageLimiter`, `maxConcurrentDownloadsPerUser`, `disableAnonymousBulkDownloads`, `maxExportSizeBytes`, `bulkDownloadAsyncThresholdBytes` | Limits |
| `passwordPolicy` | The password rules, or `null` |
| `inputRules` | The input rules that a client checks before it sends a form. `slug` and `email`: `{pattern, minLength, maxLength, description, message}`. `entryName`: the rule of a file or folder name, with `reservedNames` (in every folder) and `rootReservedNames` (at the dataset root). `nameClash`: the message of a name that a folder already holds (`A file or folder named '{name}' already exists in this folder`) and `caseInsensitive`. `cron`: the `disableWords` that turn a scheduled job off. `latinName`: an organization or dataset name needs a Latin letter or a digit, unless you give a slug. Each `pattern` is a JavaScript regular expression. The server still checks every value. |
| `systemRoles` | The roles the server depends on: `admin` and `deactivated` (blocks sign-in). They cannot be deleted. |
| `datasetThumbnailCandidates` | The file names that give a dataset its thumbnail, in order |
| `updateCheckEnabled`, `instanceHash` | The update check of the instance |
| `hubOptions` | Branding and feature flags of the web app |

`GET /sys/version` returns the Registry version.
